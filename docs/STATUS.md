# Feature status ledger

One row per user-facing feature: how far it has been proven, on what, and what is still open. This is the one place
that answers "does it work on the Mini V2?". Every "Status" note in the other documents (and the manual's notes for
players) has to agree with it. State as of 2026-10-28, main `d908a14`; rows older than that keep the date of the run they describe.

**The rule: whoever changes how well a feature has been verified updates its row in the same commit.** That means a
new feature (add its row), a device run (move the row up and write what was done), a regression (move it down), and a
note in any other document that makes a claim about the device (change it to match, or link here). When a note and
this table disagree, the table is wrong or the note is stale; settle it before you merge.

## Statuses

Each row has exactly one of these, the weakest that is true for everything the row names. If half a feature is proven,
the row is split.

| Status | Means |
|---|---|
| **device-measured** | Run on the Retroid Pocket Mini V2 and measured: numbers or a repeatable procedure were recorded (a latency run, a benchmark, an A/B of logs). |
| **device smoke-checked** | Run on the Mini V2 and seen to work (it starts, shows the right thing, does the basic job). No numbers, no endurance, no second case. A smoke check is not an endurance test. |
| **virtual device only** | Built and driven in the Docker virtual device ([VIRTUAL-DEVICE.md](VIRTUAL-DEVICE.md)) with its stand-ins (no battery, radios, fan, panel or GPU). Not run on the Mini V2. |
| **host tests only** | Unit tests, snapshots or code reading on a development machine. Not even driven in the virtual device. |
| **not built** | Planned or promised somewhere, with no code behind it (or code that is switched off). |

"Device" always means the one Mini V2 the project is developed on (ROCKNIX 20261001). Nothing is proven on a second
device, a different card, or by someone who did not watch it being built. The sources are the Status notes of
`docs/`, `docs/latency/*.json`, the git log, and the overnight and review notes of 2026-10-22 to 24 (kept outside the
repository; their evidence is summarised in the rows). The notes' dates are the days the work was done.

Unticked boxes in [DEVICE-TESTS.md](DEVICE-TESTS.md) are a to-do list for a person at the device, not a record: a box
can be unticked while a later run (named here) covered the same ground.
